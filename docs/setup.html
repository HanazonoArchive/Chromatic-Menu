Set up Supabase for the dashboard

This takes about ten minutes and is done once. Supabase stores the heartbeats your PCs send and the game requests customers submit. The free plan is enough for a small shop.

Only ever use the anon / public key, in Chromatic Menu and in this dashboard. Never paste the service_role key anywhere: it bypasses all security.
1

Create a Supabase project

  1. Go to supabase.com and sign up for a free account.
  2. Click New project. Give it a name (for example pisonet), set a database password, and choose the region closest to you (for the Philippines, Southeast Asia (Singapore)).
  3. Wait a minute or two while the project is created.
2

Run the database schema

  1. In your project, open SQL Editor from the left menu and click New query.
  2. Click Copy below, paste everything into the editor, and click Run.
  3. You should see Success. Running it again later is safe; it never deletes your data.

It creates the tables, the security rules (the public key can only add data, never read it), the functions the dashboard uses, and two scheduled jobs that summarise each day and remove raw heartbeats older than 90 days.

The same file is in the repository at docs/supabase/schema.sql.

3

Turn off public sign-ups

Only accounts you create yourself should be able to open the dashboard.

  1. Open Authentication, then Sign In / Providers.
  2. Turn off Allow new users to sign up and save.
4

Create your dashboard login

  1. Open Authentication, then Users, and click Add user, then Create new user.
  2. Enter your email and a strong password, and tick Auto Confirm User.
  3. Repeat for anyone else who should see the dashboard.
5

Copy the project URL and anon key

  1. Open Project Settings, then API (or Data API and API Keys).
  2. Copy the Project URL, for example https://abcdefgh.supabase.co.
  3. Copy the anon / public key (a long text starting with eyJ).
6

Connect the PCs and the dashboard

On each PC (booted Thawed if Deep Freeze is installed):

  1. Open Chromatic Menu, click Settings, and enter the admin password.
  2. In General, make sure Start with Windows is on. Heartbeats are only sent when it is.
  3. In Telemetry, keep Enable telemetry on, paste the Project URL and anon key (or leave them empty to use the built-in defaults), click Save, then Test connection.
  4. Check that Service shows Running. Then freeze the PC again.

In this dashboard: open the dashboard, paste the same URL and anon key, and sign in with the account from step 4. You stay signed in on that browser until you log out.

7

Troubleshooting

  • No PCs appear. On the PC, Settings, Telemetry should show Service: Running, and Start with Windows plus Enable telemetry must both be on. The service log is at C:\Program Files\Chromatic Menu\data\logs\telemetry.log.
  • "The database is not set up yet". Step 2 was not run, or it ran on a different project than the URL you entered.
  • Sign in fails. The user must exist in Authentication, Users and be confirmed.
  • Game requests fail on the PC. Each PC can send one request every 5 minutes; titles are limited to 100 characters and details to 500.
  • Check that data is private. This command uses the public key to try to read heartbeats. It must return an empty list [] or a permission error, never data: 
    curl "https://YOUR-PROJECT.supabase.co/rest/v1/heartbeats?select=*&limit=1" -H "apikey: YOUR-ANON-KEY" -H "Authorization: Bearer YOUR-ANON-KEY"
